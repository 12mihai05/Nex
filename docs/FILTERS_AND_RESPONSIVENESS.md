# Filters and responsiveness

Updated design: Movies, Series and Filters now operate inline on Home, retaining the hero and personalized horizontal shelves. Exact inclusive minimum/maximum duration is always visible in Filters; setting it selects Movies. Global constraints intersect with shelf constraints and also apply to Pick for me. Filter snapshots are reused within the screen and manual refresh retains its confirmation. The old separate grid screen has been removed. Retrieval and hard filtering stay server-side, with existing personal ranking and owned-provider scope. No AI calls or persistent taste changes for filters.

Separate TV listings and the country-scoped, paginated channel guide into tabs. Keep guide input state stable, ignore stale responses, cache repeated guide queries briefly, and update favorites optimistically with rollback. Channel favorites are managed in the guide only, with no duplicate Profile entry. Previews include every favorite in the retrieved window plus non-favorites; each time window has See all with paginated listings and Favorites only. Up to 50 favorites per viewer/country are supported; the country-wide 120-channel favorite sync cap remains. A fixed window timestamp prevents pagination drift as the clock advances.

Use a reusable, reduced-motion-aware animated skeleton for pending content. Poster placeholders share grid dimensions and poster ratio with result cards, including separate title/metadata lines; onboarding uses its own exact grid geometry. TV uses individual 270px cards, and channel lists use title/subtitle/star rows. Placeholder counts scale with the available viewport. Home and title placeholders follow the hero/row and backdrop/detail layouts. Disable duplicate pick actions and retain failure/retry states. Reduce light-mode glare, strengthen selected burgundy accents, and explicitly set contrasting system-bar icons without changing the dark palette.

Verify range semantics and authorization on the backend; verify input retention, pending actions, rollback, navigation, light contrast and large text in Flutter. Render actual screens and build Android. Do not expose secrets or change production accounts.

Onboarding follow-up: title-only preview search uses a single TMDB search request without per-result metadata/availability hydration. Selected movie/series identities are stored independently of the current search results and submitted to the existing taste endpoint (five maximum). Full trusted title metadata is resolved by the backend when learning from selections. Debouncing, cancellation, stale-result guards and a bounded in-memory search cache apply.

References consulted: Flutter [TextField controller lifetime](https://api.flutter.dev/flutter/material/TextField-class.html), [system overlay styles](https://api.flutter.dev/flutter/material/AppBar/systemOverlayStyle.html), and TMDB [movie discovery runtime bounds](https://developer.themoviedb.org/reference/discover-movie).
