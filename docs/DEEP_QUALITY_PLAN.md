# Extended pre-deployment quality pass

1. Exercise twelve mixed/topic-first synthetic personas through real authenticated endpoints, without forcing genre selections. Include idea-driven fiction, workplace satire, competence/process stories, nature, relationships, animation, international cinema, comfort, horror exclusions, contradictory wishes and adversarial text.
2. Inspect extracted signals, actual catalog premises/tags, score evidence, Chat responses and multi-turn changes. Separate objective constraint failures from subjective relevance. Keep a reproducible local evidence artifact containing synthetic prompts/public catalog data only.
3. Fix demonstrated weaknesses with bounded content-based retrieval/ranking and regressions. Do not introduce a vector database or an LLM-generated catalog. Repeat targeted failures and the full suite.
4. Resolve the development-tool advisory with a compatible, verified dependency resolution. Re-run migrations/build/tests and dependency audit.
5. Render major Flutter screens in dark/light and narrow/large-text layouts; inspect actual images and fix errors. Discover available Android tooling/devices and test notifications only if a real device is available. Distinguish mocks/emulators from hardware delivery.
6. Re-run security, cleanup, retention and regression checks; write a candid report. No deployment in this pass.

Evaluation follows the official OpenAI guidance: representative, edge and adversarial cases; explicit criteria; repeated regression runs; no claim that one model judgment proves satisfaction. Source: https://developers.openai.com/api/docs/guides/evaluation-best-practices
